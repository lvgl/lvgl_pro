## Overview

With the help of subjects, the interface of the UI can be created.

A subject is a data item whose value can be set either from the
application or the UI, and whose value can be bound to widget
properties. Most subjects are global, shared by the whole UI, but a
Component can also have [subjects of its own](#local-subjects).

<Callout type="info">
Designing in Figma? You can bind layers to subjects directly in the Figma plugin, no code required. See [Subjects & Data Binding in Figma Flow](../figma/subjects).
</Callout>

For example, a `room1_temperature` subject's value can be set in the
application when the temperature is measured, and can be bound to a
label like this:

```xml
<!-- Wrap subjects and expressions in @{ } to create a binding. -->
<lv_label text="@{room1_temperature}"/>
```

Some widgets also define dedicated `bind_*` properties, for example `<lv_slider bind_value="subject_1"/>`. They take a single subject without an expression, and most of them are two way. See [Widget specific bindings](#widget-specific-bindings).

## Defining subjects

Subjects can be created in `globals.xml` like this:

```xml
<globals>
  <subjects>
    <int name="battery_power" value="32" min_value="0" max_value="100"/>
    <string name="user_name" value="John"/>
    <float name="room_temperature" value="21.5"/>
    <color name="accent_color" value="0xff8800"/>
    <pointer name="avatar" value="img_default_avatar"/>
  </subjects>
</globals>
```

As the example shows, a subject consists of a type, name, and initial value. These types are supported:

| Type | Value | Note |
|---|---|---|
| `int` | a whole number | `min_value` and `max_value` clamp it |
| `float` | a number with a fraction | `min_value` and `max_value` clamp it |
| `string` | text | |
| `color` | `0xRRGGBB` or `0xRGB` | |
| `pointer` | a **name**, not a pointer | for an image, a font, or anything else XML addresses by name |

A `<pointer>` subject holds the name as written, and whoever uses it resolves the name, so `<lv_image src="@{avatar}"/>` works for a compiled-in image and for a file just the same.

The initial value can be a constant or an [expression](./evaluate#outside-the-view) of constants, e.g. `<int name="battery_power" value="{full_charge / 2}"/>`.

<Callout type="info">
Float subjects require `LV_USE_FLOAT` to be enabled in `lv_conf.h`. Without it, the generated code fails to compile.
</Callout>

## Binding widget properties

### Generic bindings with expressions

The simplest way to create bindings is to wrap subjects and optional expressions into `@{ }`. For example:

```xml
<lv_label text="@{'My name is ' . subject_first_name . ' ' . subject_last_name}"
          hidden="@{variant_mode == no_details}"/>
```

Inside `@{ }` names are written as **bare identifiers** (without `$` or `#`). The following symbols can be used:

- **Subjects** - from `globals.xml`, or [local to the Component](#local-subjects).
- **Variants** - the Component's own reactive state. A variant name reads the currently selected option, and the option names can be used as constants. See [Variants](./variants).
- **Constants** - they are inlined as literals.
- **`bindable` properties** - see [Bindable properties](#bindable-properties) below.
- **`type="subject"` properties** - see [Following a different subject per instance](#following-a-different-subject-per-instance) below.

A plain `<prop>` can be used too, but it is **snapshotted**: its value is frozen into the expression when the instance is created. That is what lets an instance identify itself inside its own bindings:

```xml
<!-- tab.xml: `index` is a plain <prop>, `active_tab` is a subject -->
<view extends="lv_button" hidden="@{active_tab != index}"/>
```

```xml
<!-- Every tab watches the same subject, but compares it to its own index -->
<tab index="0" text="Home"/>
<tab index="1" text="Settings"/>
```

A snapshot never tracks the property, so mark the property `bindable="true"` if it has to.

A binding also has to reference at least one subject, otherwise it could never update. `@{10 > 20}` is reported and ignored, and the widget is still created normally. Use `{ }` for a value that is decided once.

`@{ }` works on the attributes of **widgets**: on the `<view>` itself, on any widget inside it, and on local style properties (`style_bg_color`, `style_pad_all-pressed`, ...). On a Component instance it works on its [variant](./variants) attributes and on its `bindable` properties.

It can't be used in the `<styles>` section, as [styles](./styles) are initialized only once:

```xml
<!-- ❌ A style is initialized once, so it can't be bound -->
<style name="style_main" bg_color="@{subject_theme_color}"/>

<!-- ❌ `title` is a plain property of my_card, so it would be frozen at creation -->
<my_card title="@{subject_user_name}"/>

<!-- ✅ Simple bindings to common widget properties -->
<lv_slider hidden="@{!subject_settings_show}" disabled="@{!subject_settings_active}"/>

<!-- ✅ `text` comes from `lv_label` that `h3` extends. 
     It means a binding can be used on it.-->
<h3 text="@{'Hi ' . subject_name}"/>

<!-- ✅ `tone` is a variant of my_card -->
<my_card tone="@{subject_alarm == 1 ? danger : normal}"/>

<!-- ✅ `reading` is a `bindable` property of my_card -->
<my_card reading="@{subject_temperature}"/>

<!-- ✅ Bind inside the Component, and pass the subject to it
     (`title_subject` is a `type="subject"` property of my_card) -->
<my_card title_subject="subject_user_name"/>

<!-- ✅ A whole style switched on and off -->
<lv_obj>
  <style name="style_warning" enabled="@{subject_temp > 30}"/>
</lv_obj>
```

Every one of these attributes also accepts a plain `{ }` [expression](./evaluate), which is the same expression evaluated **once**, when the element is created. The braces are the only difference:

```xml
<!-- Hidden or not is decided at creation, and stays that way -->
<lv_slider hidden="{!settings_show}"/>

<!-- Hidden follows the subject for as long as the widget lives -->
<lv_slider hidden="@{!subject_settings_show}"/>
```

Use `{ }` for a value a property or constant decides, and `@{ }` for a value that has to keep up with the application. Learn more about the expression syntax itself on the [Evaluate expressions](./evaluate) page.

### Bindable properties

A plain `<prop>` is consumed while the instance is created, so it can't change afterwards. Adding `bindable="true"` gives the property a subject of its own in every instance, so it can change:

```xml
<!-- thermostat.xml -->
<component>
  <api>
    <prop name="reading" type="int" default="20" bindable="true"/>
    <prop name="unit" type="string" default="C"/>
  </api>

  <view extends="lv_obj">
    <lv_label text="@{reading . unit}"/>
    <lv_bar value="@{reading}"/>
  </view>
</component>
```

The property can then be

- set to a starting value, as usual: `<thermostat reading="18"/>`
- bound where the Component is used: `<thermostat reading="@{subject_kitchen_temp}"/>`
- read in the Component's own bindings, as `@{reading}` above
- written from C with the generated `thermostat_set_reading()`, and read with `thermostat_get_reading()`

`unit` in the example is a plain property, so `@{reading . unit}` follows `reading` and freezes `unit`. Both are per instance: two thermostats can show `18C` and `40%` at the same time.

### Local subjects

A `<subjects>` section inside a Component or a Screen declares subjects that belong to the **instance**, not to the whole application. Every instance gets its own:

```xml
<component>
  <subjects>
    <int name="taps" value="0" min_value="0" max_value="99"/>
  </subjects>

  <view extends="lv_button">
    <lv_label text="@{'Tapped ' . taps . ' times'}"/>
    <set_subject_event subject="taps" value="taps + 1" trigger="clicked"/>
  </view>
</component>
```

A local subject is private: it can't be set from the outside, so it always starts at its declared `value`. It also shadows a global subject of the same name. The same `<subjects>` section in `globals.xml` means the opposite, one subject shared by everything.

Use a local subject for state that only the Component cares about, like which tab is open inside it. Use a `bindable` property when the value comes from outside, and a global subject when several parts of the UI share it.

### Following a different subject per instance

Referencing a subject by name in the component makes every instance follow the *same* subject. To let each instance follow a *different* one, declare a `type="subject"` property and pass the subject's name where the Component is used:

```xml
<!-- room_card.xml -->
<component>
  <api>
    <prop name="temperature" type="subject"/>
  </api>

  <view extends="lv_obj">
    <lv_label text="@{temperature . ' °C'}"/>
    <lv_obj style_bg_color="@{temperature > 25 ? 0xff8800 : 0x0088ff}"/>
  </view>
</component>
```

```xml
<!-- screen -->
<room_card temperature="subject_kitchen_temp"/>
<room_card temperature="subject_bedroom_temp"/>
```

The value has to name an existing subject. If it doesn't, the binding is skipped with a warning.

### Widget specific bindings

Some widgets (e.g., label, slider) support binding the subject's value
directly to the widget. These bindings use attributes that start with
`bind_*` and reference a subject.

```xml
<lv_slider bind_value="some_subject"/>
<lv_label bind_text="some_subject" bind_text-fmt="%03d Volts"/>
```

Most of these are two way bindings: the widget can set the subject and the subject can set the widget too. If the subject's value changes (for example because the user dragged the slider), every widget bound to it is updated automatically.

`lv_label` also accepts a format string, which `@{ }` cannot do, so `bind_text` is the way to control the number of digits or decimals.

### Old syntax

Before `@{ }` existed, flags and states were bound like this:

```xml
<lv_label text="Hello world">
  <lv_obj-bind_flag_if_eq subject="subject1" flag="hidden" ref_value="10"/>
  <lv_obj-bind_state_if_gt subject="subject1" state="checked" ref_value="20"/>
</lv_label>
```

`bind_flag_*` takes a `flag`, `bind_state_*` takes a `state`, and both come in `_eq`, `_not_eq`, `_gt`, `_ge`, `_lt`, and `_le` variants. The `lv_obj-` prefix is optional.

These still work, but `@{ }` is more powerful and replaces all of them, so it's recommended to migrate:

```xml
<lv_label text="Hello world" hidden="@{subject1 == 10}" checked="@{subject1 > 20}"/>
```

## Variants

A subject is global, but a Component often needs reactive state of its own, for example whether a badge is `normal` or `danger`. That is what a [variant](./variants) is: a named list of options declared in the Component's `<api>`, with its own value in every instance.

Variants are used in bindings exactly like subjects:

```xml
<!-- Inside the Component that declares the `tone` variant -->
<style name="style_danger" enabled="@{tone == danger}"/>
<lv_label text="@{tone == danger ? 'Alert' : 'All good'}"/>
```

```xml
<!-- Where the Component is used, the variant can follow a subject -->
<my_badge tone="@{subject_alarm == 1 ? danger : normal}"/>
```

Inside an expression a variant name reads the currently selected option, and an option name acts as a constant. See [Variants](./variants) for declaring them and for setting an option from C.

## Switching a style

A binding can turn a whole style on and off, through the `enabled` attribute of a `<style>` element. See [Conditional styles](./styles#conditional-styles).
