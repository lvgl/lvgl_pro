# Figma to XML

Read `AGENTS.md` at the project root first, if it is not in your context. Follow its
"Working with the user" rules.

The export itself is done by the user, in Figma and in the Editor. The plugin has no
command line. This skill starts after the export. Docs:
[Figma plugin](https://lvgl.io/docs/pro/figma).

## Steps

Show this checklist to the user and keep it up to date.

1. Check the export
2. Check with the CLI
3. Compare with Figma (optional)
4. Write the review
5. Do what the user selects
6. Report

### 1. Check the export

- Find the files that start with `<!-- Generated by LVGL Figma Flow | This file is OWNED_BY=FIGMA -->`,
  or with the same line and `OWNED_BY=USER`. If there are none, tell the user how to export
  ([Get started](https://lvgl.io/docs/pro/figma/get-started)) and stop.
- Read `FONTS-MISSING.md` if it exists. Each font in it needs a TTF in `fonts/`. Ask the
  user for the files.
- Read `project.xml`. The plugin supports one display size. Ask if it is correct.

**Ownership.** A re-export rewrites every `OWNED_BY=FIGMA` file from zero. A file that
says `OWNED_BY=USER` is skipped, so later design changes do not reach it. Before you edit
a `FIGMA` file, tell the user, and ask whether to:

- put the change in a new file (a new component, or a screen that uses the exported
  ones), so the exported file stays `FIGMA`; or
- change the header to `OWNED_BY=USER` and edit the file.

### 2. Check with the CLI

```bash
lvglpro validate . --errorlimit 25
lvglpro generate .
lvglpro compile .
lvglpro screenshot . screens/<screen>.xml --out figma_review/<screen>_lvgl.png --delay 300
```

Screenshot every exported screen. Look at each image. Note what is clipped, missing, or
in the wrong place.

### 3. Compare with Figma (optional)

Do this only if a Figma MCP server is connected (tools such as `get_screenshot`,
`get_metadata`, `get_variable_defs`). If it is not, say so and go to step 4.

Calls are limited per day on most Figma plans. Count the calls you need (about 2 per
screen, plus 1) and ask before you start. Ask for the Figma file link if you need it.

- `get_screenshot` of each exported frame. Save it as `figma_review/<screen>_figma.png`.
  Compare it with the LVGL screenshot. Fonts and anti-aliasing differ a little; look for
  real differences: size, position, color, missing parts. `layout.py` and `compare.py`
  find them: see "Check and correct" in [image-to-xml/recipes.md](../image-to-xml/recipes.md).
  Put the `compare.py` image in the review too.
- `get_variable_defs`: compare the Figma variables with the constants in `globals.xml`.
- `get_metadata`: compare the layer tree, sizes, and order with the XML view tree.
  Flex layouts and `components/base/` change the nesting, so compare the result, not the
  exact structure.

The MCP server cannot read the plugin's annotations, so it cannot tell which layers are
widgets.

### 4. Write the review

Write `figma_review/index.html`: one self-contained page, no external files except the
PNGs next to it. Contents:

1. Per screen: the LVGL image. With the MCP server, also the Figma image next to it, and
   the differences.
2. **XML options**, numbered. Typical ones:
   - Events and screen changes. The plugin exports none.
   - Widgets the plugin does not support yet (see
     [Widget support](https://lvgl.io/docs/pro/figma/widget-support)), now plain
     `lv_obj` or labels.
   - Missing states: only states with a Figma variant are styled.
   - Animations, translations, tests, more targets.
   - Fixes for the differences found in steps 2 and 3.
3. **Figma design options**, numbered, only with the MCP server. For example: a raw
   color that should be a variable, a frame without auto layout, a repeated group that
   should be a component, a missing variant for a state, unclear layer names.

For each option, write one line: what, where, and the effort (small, medium, large).
Tell the user the path, and ask which numbers to do.

### 5. Do what the user selects

Do the XML options one at a time. After each one, run `validate`, `generate`, `compile`,
and `screenshot`, as in step 2, and `run-all-tests` if the project has tests. Without
`generate` and `compile` the screenshot can show the old build. The
Figma options are for the designer; do not change the Figma file.

### 6. Report

- The options done, and the files changed, with their `OWNED_BY` value.
- The files that a re-export will now skip.
- What is not verified.
